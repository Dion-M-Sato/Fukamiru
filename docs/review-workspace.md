# レビューの作業画面と回答

レビュー待ち一覧は、中央で対象の選択、全体コメント、回答の送信、承認を行う。
右ペインは「質問と回答」「対象のHTML」を切り替える。HTMLの拡大表示にも同じ配色と本文書式を使う。
狭い画面では右ペインを前面に表示し、「一覧と全体コメントへ」で戻る。

## 保存とフィードバックの契約

`0053_review_feedback.sql` は質問と対象HTMLのスナップショット、質問IDごとの自由回答、
`llm_overreach`、全体コメント、下書きの版、送信した版を保存する。
更新時は版番号を検査し、別画面の保存を上書きしない。
切替時には待機中の自動保存を即時実行し、保存前の再読込にはタブ内の復元用下書きを使う。
別画面で更新されていた場合は復元内容を別に提示し、自動では上書きしない。
送信済みの回答は、中央の「送信した回答の履歴」から再表示できる。
承認や再生成後の記録は読み取り専用になる。

生成・修正・再監査には送信済み回答だけを渡し、プロンプトとチェックポイントの入力にも含める。
既存の推敲・再監査アダプターが読む`human_review`にも同じ判断を渡し、元の著者コメントを保つ。
各ノードで同じ回答を重複追記しない。
同じ対象・分類・要求に対する判断は、監査IDだけが変わっても再利用する。
過剰要求は確認項目の`dismissed`、自由回答は`resolved`として扱う。
これは人間のレビュー判断の解決状態であり、資料が支持するという事実の確定ではない。
未知の出典ID・壊れた参照などの構造検証は迂回しない。

原稿生成V31/V32の最終レビューは「回答を反映して再生成」で
`start_paragraph_formation`へ戻す。固定した論証、保護された人間の本文、旧レビュー記録を維持し、
新しいfan-in世代を開始する。元のpending proposalは既存の再検証履歴へ保存したうえで更新する。
前世代の段落と出典の対応、校正・脚注・提出検査の派生結果は初期化し、新しい本文を監査し直す。
元の値は保存済みノード入力に保持し、保存場所とハッシュを世代の履歴へ記録する。
固定資料・保護された本文・著者回答・校正の利用者設定は引き継ぐ。
著者の再生成依頼を示す`authoring_submission_revalidation`も保持し、本文の派生結果に含めない。
同じ未承認提出候補を置き換えるときは、旧本文と確認内容を不変の履歴へ保存する。
旧版がこの印を初期化して最終保存で停止した場合は、元入力と初期化履歴のハッシュ、
資料・回答・対象文書の一致、送信済み回答に対応する修正依頼と未承認候補を照合して復元する。
新本文と検査結果は変えず、新しい最終保存の試行へ一度だけ戻す。承認済み候補は復旧対象外とする。
校正文・校正候補・タイトル照合も本文世代ごとに分け、前世代の候補・選択・適用・ログを保持する。
同じ世代の元本文が変わった場合は停止し、新しい世代の校正へ旧候補を混ぜない。
段落の出典対応は、引用を付けないと確定した段落も投影済みとして保持する。
推敲が本文だけを返したとき、その空の対応を未作成と解釈して節の候補資料を再配分しない。
旧版の余分な投影で校正後の脚注が停止した場合は、起草の厳格な根拠対応と既存引用を照合し、
余分な対応が引用なしの停止段落だけであり、現本文の厳格な脚注計画が通る場合に限定して復旧する。
元の失敗入力・本文・資料・著者回答・校正結果を保持し、一度だけ校正後の統合へ戻す。
「場面が確認されていない」などの留保は、不確実性の指摘を保持して脚注後の本文修正へ渡す。
残る留保は段落を示した未解決の著者確認とする。入力メモ・草稿などの内部作業ラベルはこの経路に混ぜず、
書誌不整合・根拠改変・脚注位置の検査は維持する。留保だけで停止した旧版の再開は、
根拠対応と脚注計画の有効性を確認できる場合に限り、元入力を変更せず一度だけ行う。
承認と却下の従来の処理も維持する。
改稿案からの再改稿と翻訳の修正にも送信済みの個別回答を渡す。

質問本文は日本語の確認文とし、診断原文や内部IDは「質問の記録」に保持する。
生成側の文IDはcanonical HTMLの段落IDへ対応付け、抜粋が段落か節かを表示する。
存在しない段落を別の段落へ置き換えない。一貫性監査の人間判断・追加調査も質問に含め、
脚注付き本文の新しい監査が古い指摘を解消した場合は、古い質問を復活させない。
保存済み質問の表示を補う場合も、元のスナップショット・質問ID・回答・版番号は変更しない。
元メモの命題・主張IDを指す質問には、対応する整理内容を生成本文と区別して添える。
同じ指摘が個別レビューと情報要求の両方にある場合は、既存の質問IDを使って一問にまとめる。
情報要求の`scope`も対象範囲として引き継ぎ、送信済み回答と対象・要求文が一致する重複を除く。
旧版で対象範囲を落とした保存質問は、元の要求から同一性を復元できる場合だけ開いたレビューの
表示から除く。保存済みスナップショット・質問ID・回答・版は変更しない。入力済みの現在の下書きと
閉じた履歴は表示を保持し、別の対象や要求を同じ回答で解決しない。

脚注の書誌検査で停止した場合、著者の過剰要求判断を使って書誌を検証済みにしない。
一次の出版社・図書館情報を実際に確認した運用者向けに、限定再開APIで書誌補正を受け付ける。
対象はV32の著者未確認による脚注停止で、保存済みの文献をISBNまたは書名・著者・出版社・年で
同定でき、脚注と参考文献の厳格な書式検査を通る場合に限る。確認元、元入力、元の書誌を履歴に残す。
本文、論証、外部主張の支持判定、著者の回答は変更しない。この経路は同じRunで一度だけ。
既定の2試行が同一入力・同一エラーだった場合は、失敗履歴を残して最新試行だけを再開する。
過去の入力やエラーが異なる場合は拒否する。
