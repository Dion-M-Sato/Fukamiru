# 原稿生成の補助検索とOCR資料のRAG登録

既知書名の確認経路とOpenAlex・Crossref・NDL・Semantic Scholarの公式APIは維持する。
V32は先に既存RAGの本文を根拠検査し、未解決の命題だけを最大4テーマまで追加調査する。
公式APIの追加検索と根拠検査を行っても不足するテーマに、RustXNGの一般Web検索を補助的に使う。
短い検索語、プランナーの同義語・対抗概念、日本語と英語を使い、一つの検索語に全論点を詰め込まない。

RustXNGは別のローカルサービスとして起動し、`translation.rustxng_url`で接続する。
既定は`http://127.0.0.1:29483`。起動例は`rustxng --bind 127.0.0.1 --port 29483`。
端末固有の設定は無視対象の`config/local.toml`に置く。
補助検索は`research_web_enabled`、PDF画像OCRは`research_pdf_ocr_enabled`で切り替える。
プロキシ不通は診断記録に残し、既存DBから取得済みの根拠検査を取り消さない。

検索結果・スニペット・語句の一致だけでは根拠にしない。候補のページを取得してから引用照合する。
本文を根拠検査に渡した上位候補は、関連する逐語引用が残らなければ関連文献の提示対象からも外す。
部分的な関連引用はサジェストに残せるが、支持根拠としては別に判定する。
書籍の紹介・目次は書籍本文と区別して書誌情報として保持する。学術書の本文は論文と同じく、
確認した命題を支える範囲で採用する。未読書籍も関連性条件を満たせば機械判別参考文献へ残す。
DOI・ISBN・URL、および著者・年・版を伴う書誌を照合し、ローカル本文を優先して再利用する。
異なる版を同一視しない。検索と本文はSQLiteの実行内チェックポイントで共有し、失敗応答は成功として保存しない。
根拠検査の再利用は命題・文脈・出典・モデルが同じ場合に限り、別の命題への支持を流用しない。

## 暗号化PDFからの引き継ぎ

1. 公開されたPDFを容量・HTTPS・遷移先の検査を通して取得し、SHA-256を付けて保持する。
2. 表示できる暗号化PDF・画像PDFは、既存RAG処理のページ画像化と非暗号化画像PDFの生成へ渡す。
   原本を変更しない。言語判定とNDLOCR-Lite／Mistralのルーティング、再開用ページ記録も共用する。
3. OCRのページ対応と入力ハッシュを検証し、その文字列とページ位置を原稿側の根拠検査に返す。
   言語未確定・表示パスワード必須・取得エラーは未読として記録し、根拠には昇格させない。
4. 支持、推論の橋渡し、または反証として引用照合できた資料を、有用な資料として別Runへ登録する。
   反証を支持根拠へ昇格させない。単に不足と判定された資料は、この登録判定を通さない。
   同じPDFハッシュのRun作成と引き継ぎ記録は同一SQLiteトランザクションで確定する。
5. `research_source_ingestion` V1は通常の資料登録、抽出、OCR監査、構造化、Chunk生成、
   FTS登録を実行し、その後に既存の意味索引生成処理を使う。完了済みOCRは引き継ぎ、再実行しない。
   このRunは独立したキューとGPUレーンで動き、原稿生成はその完了を待たない。

引き継いだRun IDとエラーは原稿の提案コンテキストにも保存する。原稿が進行したことと、
RAG登録が完了したことは別の状態として確認する。サービス切り替えや保存済みRunの書き換えは行わない。
