# Knowledge Searchのレポート

検索APIの候補発見と、原資料の本文読解・書誌照合・報告作成を分けます。
通常のKnowledge SearchはCodexを使う保存型レポートです。
取り込みRunを開始せず、原資料やknowledge.dbの書誌を変更しません。

## 保存型AIレポート

`POST /api/search-reports`はqueryと任意の候補数を受けます（既定100、最大100）。
本文と書誌の題名・著者から候補を探し、最大5資料を選び、同姓の人物や別版を区別します。
索引、献辞、表題紙、OCRで損傷した目次や書誌カバーを本文の主張の根拠にしません。
前後の連続本文を読み、原文引用とページ位置を保存して報告へ使います。

Codexの工程は、資料・人物の選別、原資料からの書誌抽出、論点をつないだ合成、
主張・引用・使用書誌の独立検査です。各工程はGPT-5.6 Sol mediumを使用します。
要約・findingの各段落に実在する根拠を要求し、snapshotにない引用、未知の参照、
題名だけによる内容説明は決定的な検査で拒否します。

書誌は原資料の表題紙・奥付等の引用を必要とし、OCRが不確かな場合は資料ごと最大3ページの画像を添付できます。
画像のhashとページを保持し、原OCRは変更しません。
刊行日とscan/upload日、単著と共著、共同出版者、版、同姓の人物を区別します。
不足する書誌は推測で埋めず未解決として記録します。

本文読解は資料あたり最大3,000ページ・2,000,000文字、報告用contextは資料あたり10,000文字、
個別根拠は最大8,000文字、model evidence全体は最大60,000文字に制限します。
切り出した場合は範囲を明示します。本文hash、snapshot、実際のmodel入力を保持します。
根拠不足は不足として説明し、固定件数を満たすための資料追加をしません。

書誌・合成の訂正は各1回の上限があります。
providerやschemaの失敗は内容の再検討として再試行しません。
検査が成功した場合だけ、検証済みHTML・使用文献・根拠・採否をstate.dbへ保存します。
検証前の計画や内部の確認状態を完成報告の本文として表示しません。

`GET /api/search-reports`で一覧、`GET /api/search-reports/{id}`で詳細、
`GET /api/search-reports/{id}/export.html`でHTMLを取得できます。
保存済み報告を開き直しても再生成しません。モデル検査も誤りを完全に排除するものではないため、
原文・出典・採否を利用者が確認できる形で保持します。

## 任意のUIだけで動く抜粋表示

`ui/src/knowledge-excerpts.js`は`GET /api/search`だけを使い、
原文を資料別に整理する補助モードです。AI推論やDB書込みを行いません。
登録済みの書誌をそのまま表示し、未登録項目やfilename由来の仮登録を明記します。
最新10件は開いたタブのメモリだけに保持し、再読み込みで消えるためHTML保存を提供します。

`scripts/install_knowledge_excerpts_ui.py`は既存UIを維持した静的ファイルの導入補助です。
通常の保存型レポートとは別モードで、基本セットアップの必須手順ではありません。
変更前hash、同時編集検知、バックアップ、失敗時の復元を行い、サービス再起動やmigrationは実行しません。
UIリンク先の取り込み図は、保存型と抜粋型の両方の実契約から同期します。
