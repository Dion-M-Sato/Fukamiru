# 利用しながら開発する

公開するソースを共通の基準にし、日常利用の設定と実データは各利用環境で管理します。
個人設定・DB・資料を差分に含めず、気づいた不具合だけを小さな変更として取り込みます。

## 設定とデータ

`config/local.example.toml` は共有の設定例です。実際の保存先・モデルの場所・接続先は
Git対象外の `config/local.toml` に記載します。認証情報は環境変数で渡します。
`.gitignore` はすでに追跡中のファイルには効かないため、コミット前に差分を確認します。
バックアップ、ログ、生成物、監査資料はソースの配布物へ含めません。

## 修正から利用環境への反映

1. 不具合を架空の小さな入力で再現します。実行ID、原稿、実資料からコピーしたfixtureは使いません。
2. 変更ごとにブランチを作成します。並行開発には別checkoutまたはworktreeを使います。
3. 検証用の設定には、日常利用と異なるDB・runtime・ポートを指定します。
4. 影響範囲の検査と [必須検査](validation.md) を通し、`git diff --cached` で公開内容を確認します。
5. 利用環境では処理を停止し、整合性のあるDBバックアップを取ってから検査済みコミットへ更新します。
   無視対象のローカル設定を維持し、サービスを再開します。

独立した履歴を持つ非公開リポジトリのブランチを公開側へmergeしません。
修正を移す場合は必要なソース差分だけを取り込み、公開側で改めて検査・コミットします。
適用済みmigrationを変更せず、スキーマ変更は新しい番号のmigrationとして追加します。

## 原稿のHTML表示

翻訳、生成原稿、改稿案は共通のHTML表示を使います。`ui/src/theme.css` をUIと出力で共有し、
`ui/src/document.css` で本文・見出し・脚注を定義します。出力HTMLはスタイルを内包します。
`cite` は斜体にしません。表示処理は保存済みの正本や保護ブロックを書き換えません。

## 公開前の検査

`python scripts/check_publication.py` は追跡対象、`--archive PATH` はZIP/TARを検査します。
パス、トークンの既知形式、実行ID形式、履歴を示すファイル名、私用ファイルを検出します。
自動検査に加え、文書の本文、例、コミットメッセージと公開名義を人間が確認します。
